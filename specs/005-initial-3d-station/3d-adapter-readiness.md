# S01 3D 资料核对与可切换接入边界（2026-09-17）

## 已有资料与缺口

V1.3 架构 §4.1–4.4、§5.2、§8、§20 规定了设备连接复用、到位后采集、点云定位的职责和未决项；S01 的 [工位合同](contracts/station-boundary.md)与[结果模型](data-model.md)定义了软件需要的结果字段。这些是软件合同，不是已测得的相机参数。

- 《技术文件（带目录）0626.pdf》描述“高精度结构光 3D 相机”，《PLC与上位机通信接口协议.docx》§3.1.2 使用“3D 激光相机”说法；两者没有给出可签认的品牌、型号、镜头、视野、工作距离、点云分辨率、精度或采集配置。不能据此断定具体成像技术。
- 文档中的 `5120×5120` 是 **2D 相机**分辨率；`0.01 mm` 等是整机/检测要求或历史设计目标，均不是已确认的 3D 相机规格或实际定位精度。
- 现有仓库/交接资料中未发现 3D 厂商 SDK 包、示例、标定文件或真实点云。没有这些资料时不冻结 3D 参数，不写生产坐标。

## 中台负责的模拟与切换方式

当前没有专职 3D 同学，S01 的合成 3D 设备、固定输入、故障注入和双侧轨迹由中台开发负责。`Inspection.Application` 只依赖定位端口；Host 选择显式的 `Synthetic3D` 或 `Real3D` Provider，SDK/驱动仅存在于真实适配器或必要的隔离 DeviceHost 中。业务状态机和测试矩阵对两个 Provider 使用相同请求/结果合同：`TrayRunId`、`RequestId`、坐标批次、来源、设备/标定版本、坐标系、单位、槽位、姿态/高度、采集时间、结果/错误码。合成结果必须标 `synthetic`，不得自动转换成真机毫米坐标或开启生产动作。

模拟进程独立于中台运行，提供确定性双槽/空槽、重复槽、非有限坐标、错误单位、缺标定、超时、断连、迟到/错 ID 等场景；测试保留模拟进程和 Host 各自的请求/响应轨迹。相同合同测试用于将来的真实适配器，但真实设备还需单独核对物理坐标、标定及精度。切换是显式配置和部署动作，启动时核验 Provider/SDK/设备/标定版本；缺真实依赖或合同不符时拒绝真实模式，不回退到合成成功。

## 只有 SDK 时的能力边界

如果获得的是**版本明确、与目标 Windows/.NET 架构兼容的 SDK、文档、示例及合法运行依赖**，可先实现和编译真实适配器，核对初始化、设备发现/配置、触发、回调/超时、资源释放和错误映射所需的 API；只有 SDK 提供官方虚拟设备、离线回放或样本点云时，才能进一步运行相应的无硬件测试。没有相机时，真实设备连接、曝光、触发时序、现场丢帧和点云质量均不能判通过。SDK 是否包含槽位/姿态算法也须按实际 API 核对，不能把“取得点云”当作“定位结果”。

真机接入还需要：准确品牌/型号/固件与 SDK 版本和授权，目标 OS/位数/驱动；连接与触发方式、采集参数范围及光源/同步方式；原始点云格式和单位；相机到料盘/PLC 运动坐标系的标定文件、版本与验证样本；已知槽位/姿态测试件和预期；空盘规则、定位算法/阈值及失败码。仅有 SDK 不足以证明真实坐标可供运动或达到检测精度。资料到齐后另开 S01 设备对接 PR，复用合同测试，再用同一候选包按现场 W0–W5 验证。
