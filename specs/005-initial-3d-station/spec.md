## User Scenarios & Testing

### User Story 1 - 安全进入首个 3D 工位 (Priority: P1)

工程人员启动一盘测试任务后，只有取得属于本次会话的新鲜就绪与夹紧状态，系统才请求公共准备动作“移至 3D 位”；必须收到同一动作的受理及物理完成反馈，才允许触发 3D 定位。移动使用统一运动通道，实际下位机负责实体互锁。

**Independent Test**: 用独立于工作流的确定性运动设备替身，记录请求/受理/完成及 3D 触发顺序；替身与 Host 通过正式应用端口交互。

**Acceptance Scenarios**:
1. **Given** 新任务和本次会话的新鲜就绪、夹紧，**When** 3D 移位被受理且确认完成，**Then** 恰好发出一次初始 3D 定位请求，定位前无其他运动。
2. **Given** 尚无移位完成或只有受理，**When** 检查采集端口，**Then** 触发次数为零。
3. **Given** 未就绪、未夹紧、联锁触发或状态过期，**When** 请求开始，**Then** 进入 Failed、无移位与采集请求，并给出可定位原因；尚未请求开始时维持 WaitingReady。

### User Story 2 - 将有效定位绑定到本盘 (Priority: P1)

3D 端口返回属于本次请求的槽位、位置及来源；工作流只接受有效且无重复的槽位，生成稳定 PartId 与首轮 CoordinateEpoch，并停在“等待 F 托盘码”。空盘如何作为有效生产任务处理尚未定义；本阶段明确拒绝空定位。

**Independent Test**: 注入两个有效合成槽位和空/重复/无位置/错请求/迟到/超时结果，检查身份、坐标批次、阶段及后续请求。

**Acceptance Scenarios**:
1. **Given** 已确认到达 3D 位，**When** 两个不同槽位的有效定位结果到达，**Then** 创建两个稳定 PartId、CoordinateEpoch=1，发出一次 F 请求且不执行 F。
2. **Given** 空、重复或无有效位置的定位结果，**When** 处理它，**Then** 不创建有效坐标、不发 F 请求，并留下错误码及请求关联。
3. **Given** 旧请求、另一盘或超时后的迟到结果，**When** 它到达，**Then** 不改变当前任务和坐标。

### User Story 3 - 可观测故障和复核入口 (Priority: P2)

工程人员可从状态快照和结构化诊断判断失败发生在前置状态、移位受理、物理完成、3D 采集还是结果校验；运动结果未知时进入人工对账，不能自动重发。测试来源与实际设备来源必须显式区分。

**Independent Test**: 对每类故障注入固定输入，核对错误码、RunId/RequestId、阶段、时间及独立设备轨迹；重启后有未对账动作时不得伪装成功恢复。

**Acceptance Scenarios**:
1. **Given** 移位已经受理但超时或断线，**When** 无法确认物理结果，**Then** 标记 RecoveryRequired，不触发 3D、不自动重发。
2. **Given** 3D 端口异常或超时，**When** 无有效结果，**Then** 保留移动完成事实、记录失败阶段及原因，不进入 F。
3. **Given** 测试替身输出坐标，**When** 查询快照/诊断，**Then** 来源显示 synthetic，不显示为真机标定或实测通过。

### Edge Cases

- 受理与完成乱序、重复完成、另一动作完成、取消后迟到；明确失败与结果未知必须区分。
- 任务启动时或移动期间急停/安全联锁变化；上位机不覆盖 PLC 安全逻辑。
- 两次扫描同一槽、空白 SlotId/位置、非有限坐标、错误单位/坐标系、标定版本缺失。
- 3D 回调在超时后或新任务开始后到达；重连后的旧会话反馈不得推进。
- 诊断写入失败、运动通道满、模拟源误选为生产设备源；这些情况不得变成成功结果。

## Requirements

### Functional Requirements

- **FR-001**: 首工位必须有明确开始入口与唯一工作流所有者；生产入口不得默认绑定合成适配器。
- **FR-002**: 必须验证本次会话的新鲜就绪、夹紧及安全状态；通过统一运动通道请求公共准备“移至 3D 位”。实际 Modbus 点表由下位机负责人对齐后接入。
- **FR-003**: 动作受理不等于物理完成；仅匹配的完成反馈允许触发 3D。超时/断线导致结果未知时必须停在人工对账状态，不盲目重发。
- **FR-004**: 3D 定位请求/结果必须关联 TrayRunId、RequestId、预期 CoordinateEpoch；结果应带来源、坐标系/单位和标定版本或明确“合成”。
- **FR-005**: 有效初始扫描必须产生唯一槽位和有效位置，建立 PartId 与 CoordinateEpoch=1；拒绝旧、错、空、重复和不完整结果。端口与工作流不得把位置引用当成已验证的毫米坐标。
- **FR-006**: 成功边界停在 WaitingTrayCode 并发出 F 请求；本阶段不执行 F、配方匹配、算法、质量判定或整盘放行。
- **FR-007**: 状态与诊断必须至少记录阶段、稳定错误码、TrayRunId、OperationId/RequestId、来源、时间和可定位原因；关键诊断无法可靠写入时不得声称生产可恢复。
- **FR-008**: 必须提供可重复的合成场景和故障注入，通过正式应用端口走同一业务规则；每类反例应有独立期望值和设备轨迹。
- **FR-009**: 验证报告必须分开列出旧 V6 协议回归、首工位合成联调、V1.3 正式协议对接、真实 3D SDK/标定及完整整盘测试。
- **FR-010**: 同一提交的 Windows S01 候选包必须有可核对的来源、SHA-256、运行依赖与模式配置；现场测试不得在 Windows 电脑重新编译另一份代码充当同一包。
- **FR-011**: Windows 真实 PLC/3D 测试必须先完成接口、标定和现场准入核对，再由现场人员分步执行并保留中台、PLC、3D 三方轨迹；缺任一前置时该层记 `BLOCKED/NOT RUN`，不影响已实测的软件层结论。
- **FR-012**: 在没有专职 3D 同学及真实相机参数时，下位机同学交付独立合成 3D 设备接口，中台交付定位调用端与状态/错误合同；两者须以独立轨迹联调。合成与未来真实 SDK Provider 共用定位请求/结果合同并显式选择，真实模式缺 SDK、设备或标定时拒绝启动，不得回退为合成成功。SDK 单独到手只允许验证适配和可用的离线回放，不能判真机定位或精度通过。

### Key Entities

- **TrayRun**: 本盘会话、场景、当前阶段及错误状态。
- **ReadyObservation**: 来源、采样时刻、会话、就绪/夹紧/联锁状态与新鲜度。
- **MoveTo3DOperation**: OperationId、公共目标引用、受理/完成/失败/未知状态。
- **PlacementRequest/Result**: RequestId、CoordinateEpoch、来源、标定与坐标系、槽位定位。
- **PartBinding**: 稳定 PartId 与初始槽位；后续翻面重扫只能更新坐标批次。

## Success Criteria

- **SC-001**: 正常双槽样例只发生一次移位和一次 3D 定位，顺序正确，首轮坐标批次为 1，最终停在等待 F。
- **SC-002**: 前置状态、移位受理/完成、3D 结果校验、超时/迟到/断线等矩阵中的每个反例均有确定终态与零不安全后续动作。
- **SC-003**: Linux 和 Windows 的 .NET 10 构建、核心测试及首工位合成联调在 CI 可复现，测试产物明确指出独立设备模拟与正式协议覆盖范围。
- **SC-004**: 前端及下位机同学可依据同一合同独立构造输入、核对阶段、错误码与轨迹；未决硬件参数不会被默认为已确认。
- **SC-005（独立现场验收）**: 在已核对的 Windows 电脑和真实设备上，以同一候选包完成 S01 正常与批准的故障场景，三方轨迹证明先到位再定位、一次动作/一次定位、来源和标定有效；未执行时不得标记真机通过。该条件与软件 PR 合并门槛分开报告。

## Assumptions and Open Interfaces

首次 3D/F 使用不依赖配方的公共示教路径。测试槽位是合成输入，不代表真实零件或生产配方。独立 3D 接口模拟与 PLC 模拟均由下位机同学负责，中台负责消费端；设备供方/现场需提供真实相机和 SDK、坐标系/单位/标定、样件及空盘规则。正式 PLC 点表、动作序号/重连对账和实际到位信号由下位机负责人确认。这些决定不阻止本阶段抽象端口、工作流、测试和诊断实现，但阻止真机/V1.3 对接宣称通过。资料核对与 SDK 单独到手的测试边界见 [3D 接入准备](3d-adapter-readiness.md)。
