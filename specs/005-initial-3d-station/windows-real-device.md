# S01：实际 Windows 电脑与真实设备验收规程（待执行）

本规程仅验收“新鲜 Ready/夹紧→移至公共 3D 位→确认到位→初始定位→等待 F”。它不操作 F、A/B/C/D/E、翻面、判定或分拣，不代表完整整盘通过。按 [开发方案](plan.md)的 G5/G6 执行，记录在 `validation.md`；本文件是计划，**目前没有现场 PASS 记录**。

## A. 现场准入和责任

现场操作员与设备负责人先确认测试窗口、工作区域/人员、机械当前位置、适用的安全操作规程、有效急停/安全门/气压/夹紧反馈和可停止方式。真实设备控制只由现场人员在现场批准后启用；Linux 服务器和每次 PR CI 只使用独立模拟器，不远程自动发实体运动命令。现场故障试验只做设备方书面认可的项目，不通过强制短接互锁、制造碰撞或未知运动来“覆盖错误”。

进入 G6 前，由相应负责人交付并共同核对：版本化 V1.3 PLC 点表（地址基准、数据类型/字序/单位、动作目标、受理/完成/失败、会话/命令关联、停止/重连对账）、公共 3D 位/到位判据；3D SDK/固件、坐标系/单位、标定文件和有效期、已知测试件/槽位预期与空盘规则。中台确认真实 Provider 已通过合同测试且生产配置不会回退为 synthetic。任何一项缺失，G6 记 `BLOCKED`，不靠旧 V6 点表试动。

若 S01 软件 PR 合并时仍只有 synthetic Provider，必须先完成独立 S01 设备对接 PR、重建 main 候选包并完成真实适配合同测试，才可进入 G6；不得把合成包直接接现场 PLC。

## B. 与 GitHub 同一候选包

1. 选成功的 main CI 提交与 Windows S01 候选包，记录仓库、PR、main SHA、Actions run、包名、SHA-256、manifest 的 stage/版本/组件和对应的独立模拟器/PLC/3D 版本。不要在现场重新编译来替代同一包。
2. 在实际 Windows 电脑创建本轮独立目录，校验 `Get-FileHash <包.zip> -Algorithm SHA256` 与 manifest；记录 Windows 版本/架构、.NET 发布模式与运行库、SDK/驱动、网络/端口及运行账户。缺依赖先记 `BLOCKED`，不把启动失败写成工位逻辑失败。现场配置与凭据不回传仓库。
3. 先用相同包在 `FullSimulation`/受限工程模式连接独立虚拟设备，跑 N01、M02、S01 和重启后不自动运动；核对包、日志、来源标记。真实设备模式必须与模拟模式配置显式分开。
4. 在真实模式测试前，备份配置、保存设备位置/状态和标定版本；确认测试结束能按现场规程复位。现场若存在未对账的旧动作，停止，不在新会话下直接开始。

当前仓库无专用 Windows runner，现有 `windows-staging.yml` 仅有基础 Host 冒烟且阶段检查仍写旧 `EngineeringFoundation`。实现 PR 须修正并扩展它；在 runner 注册前，上述步骤由现场人员手动执行，回传标准报告。GitHub 托管 `windows-2022` 作业只证明构建和合成测试，不证明设备现场。

## C. 真实设备递进测试

每项开始前记录 RunId、设备状态、标定/配置版本及操作者；操作中同步记录 Host、PLC 和 3D SDK 的 UTC 时间或时钟偏移。每项若出现未知动作，立即按现场停机/对账流程处理，本轮不自动重试。

| 步骤 | 现场操作 | 通过条件与证据 |
| --- | --- | --- |
| W0 只读连通 | 启动 Host、PLC、3D SDK，不下发运动；读取 Ready、夹紧、联锁、设备/标定版本 | Host 快照与 PLC 物理状态一致；来源 `real`，无动作；SDK 可读取版本/健康状态 |
| W1 禁止条件 | 由现场按批准方式设置未就绪、未夹紧或互锁状态；尝试准备 | 对应 P01/P02 稳定错误；PLC 独立轨迹中 MoveTo3D=0，3D=0，F=0；物理安全处理仍由 PLC 执行 |
| W2 单次移位 | 在安全状态与已核对目标下，由现场人员批准一次真实准备 | 只下发 1 次 MoveTo3D；同一 OperationId 的受理后才允许等待，到位被 PLC 独立确认前 3D 请求为 0；停在已到位或扫描中，不能凭 PC 超时宣称到位 |
| W3 真实定位 | 在 W2 已到位后对已知测试件执行一次 3D 定位 | 3D SDK 独立轨迹恰好 1 次请求/响应；坐标系、单位、标定、槽位与预先记录的测试件期望一致；PartId 唯一、Epoch=1，最终 `WaitingTrayCode`，F **仅请求一次而不执行** |
| W4 允许的故障 | 仅由设备方从 M01/M02/M03/S01/S02 中挑选安全可控项，并预写注入/恢复方式 | 明确拒绝与 Unknown 分开；Unknown 不自动重发，不发 3D/F；3D 错误不建有效坐标。若现场不允许某项，记 `NOT RUN + 原因`，用独立模拟器结果另列，不以跳过充当 PASS |
| W5 停止/重启 | 现场确认设备静止后按批准方式停止 Host、再启动并读取物理状态 | 不自动恢复运动；未对账动作显示 `RecoveryRequired` 并需人工确认，日志可对回原 OperationId；复位由现场负责 |

本阶段不做未经批准的物理失联、急停、撞限位或拔线试验；断线/旧序号/乱序等完整逻辑故障矩阵先由独立虚拟 PLC 覆盖。若现场方案允许物理故障试验，另列风险、执行人、恢复路径和独立预期，不改写 S01 软件矩阵的原始验收条件。

## D. 报告和判定

每条用例分别写 `PASS/FAIL/BLOCKED/NOT RUN`、输入与事先冻结的预期、实际阶段/错误码、Move/3D/F 次数、操作/请求 ID、首次失败及修正复测。附：包 SHA/manifest、Windows/运行时/驱动与设备版本、PLC 原始事件/状态、3D SDK 请求结果与标定引用、Host 结构化日志、界面/操作录像或照片及现场操作者/复核人。轨迹只需必要元数据和受控样本引用；真实生产凭据、秘密配置不入仓库。

任何失败先保留现场，再按“触发→软件为何未防止→测试为何漏检→修正是否生效”定位，并在新修复 PR 重跑受影响的服务器/CI/Windows 软件层和该现场用例。三方轨迹不一致、未知动作未对账或实际来源/标定缺失时不可判 PASS。WPF 尚未交付时，WPF 页面/原生交互另列 `NOT RUN`；这不改变 PLC/3D 设备链的实际结果。
