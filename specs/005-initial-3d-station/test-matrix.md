# 首工位测试矩阵与证据分层

每一行使用固定输入和独立期望，记录 RunId、操作/请求 ID、设备与中台两侧轨迹、最终阶段/错误码、3D 触发次数、F 请求次数；失败时还记录异常类型和发生层。测试不能靠同一生产编码器自己生成预期值。`WaitingTrayCode` 只表示首工位完成。

3D 故障分层：独立相机模拟器注入采集超时/断连/错 ID/坏帧，中台合成定位器注入空/重复槽、坏坐标/单位/来源；跨进程测试须同时看到设备采集轨迹和中台定位轨迹，不能让相机模拟器直接返回槽位冒充定位。

| 编号 | 输入/故障 | 预期阶段 | 移位/3D/F 次数 | 关键断言 |
| --- | --- | --- | --- | --- |
| N01 | 新鲜 Ready/夹紧、受理+到位、两有效槽 | WaitingTrayCode | 1/1/1 | PartId 唯一、Epoch=1、来源 synthetic |
| P01 | 请求开始时未就绪或未夹紧 | Failed | 0/0/0 | 明确前置原因；未请求时仍 WaitingReady |
| P02 | 请求开始时联锁触发或就绪过期 | Failed | 0/0/0 | 禁止发运动 |
| M01 | 移位明确拒绝 | Failed | 1/0/0 | 受理失败与物理未知分开 |
| M02 | 已受理未完成/超时 | RecoveryRequired | 1/0/0 | 不重发，不发 3D |
| M03a | 已受理后断线且无可信完成 | RecoveryRequired | 1/0/0 | 不能用重连当成功 |
| M03b | 完成 ID 错/旧会话，在期限内注入 | MovingTo3D | 1/0/0 | 旧反馈忽略；期限到达后变 RecoveryRequired |
| M04a | 匹配完成先于匹配受理 | MovingTo3D | 1/0/0 | 不触发 3D；后续有效完成另测 |
| M04b | 正常已到位后重复完成 | Scanning3D | 1/1/0 | 3D 仅触发一次 |
| S01 | 3D 超时/异常 | Failed | 1/1/0 | 记录采集失败，F 不执行 |
| S02 | 空槽列表、重复或空白槽/位置 | Failed | 1/1/0 | Epoch 不建立，错误码稳定 |
| S03 | 非有限/错误单位、标定缺失的真实坐标 | Failed | 1/1/0 | 不能以引用冒充有效毫米坐标 |
| S04a | 扫描期限内旧 RequestId/另一盘结果 | Scanning3D | 1/1/0 | 无身份和坐标串盘；期限到后 Failed |
| S04b | 扫描超时后迟到结果 | Failed | 1/1/0 | 不复活超时任务 |
| O01 | 诊断/关键保存失败 | Failed/RecoveryRequired | 不增加后续动作 | 不得报告成功或可恢复 |

每行在列出的事件到达点立即断言；随后期限或有效完成到达时再单独断言转移。计数和阶段是精确期望，不把允许范围当成通过标准。

Linux 本地和 GitHub Ubuntu/Windows 的独立合成测试须覆盖上表全部适用行。实际 Windows 电脑先以同一候选包跑合成 N01、P01/P02、M02、S01、重启无自动运动；真实设备按[现场规程](windows-real-device.md) W0–W5 递进，物理故障只做现场批准项。每个层级均单独记录 `PASS/FAIL/BLOCKED/NOT RUN`，不能把被跳过的真机行合入合成通过率。若 Windows 真机对某场景有不同安全预期，应先记录经设备方确认的预期版本，不能在失败后追改原期望。

| 测试层 | 本阶段期望 | 不能据此声称 |
| --- | --- | --- |
| 现有核心/旧 V6 协议 | 合并后 main 与首工位 PR 持续通过；独立列结果 | V1.3 点表或工位运行 |
| 首工位状态/合成 Host 联调 | N01 与故障矩阵，真实调用中台入口和独立适配器 | 真机到位、真实 3D 精度 |
| V1.3 PLC 双进程对接 | 点表和动作语义冻结后另测，当前 NOT RUN | 旧 V6 通过不能替代 |
| 真实 3D SDK/标定 | 实物样件及坐标基准到位后另测，当前 NOT RUN | synthetic 槽位不能替代 |
| 完整整盘/配方/算法/桌面 | 后续工位与资源到位后另测，当前 NOT RUN | `WaitingTrayCode` 不是整盘完成 |
