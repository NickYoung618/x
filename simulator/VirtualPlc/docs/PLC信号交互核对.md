# PLC 信号交互核对报告

## 1. 核对基准与结论

核对基准为 `资料/制冷机零件缺陷检测SRS_PLC接口设计规范报告.docx`，修订日期 2026-09-08，V6.0 最终版。

结论分为两层：

- **点表层一致：**规范中的 8 个线圈和 21 个保持寄存器已全部实现，地址、名称、方向和枚举值一致，共 29/29 个信号。未增加私有 Modbus 信号。
- **交互层在现有点表可表达的范围内一致：**虚拟 PLC 作为 Modbus TCP Slave/Server，上位机作为 Master/Client；已实现心跳、3 秒超时、系统就绪、安全互锁、区域配置握手、XY/Z 到位、翻转角度、分拣状态、托盘锁紧、人工介入和重试命令的基础行为。
- **不能认定整份规范“严格完整实现”：**V6.0 文档本身缺少故障码地址、分拣目标区域及区域占用量等必要信号，部分验收项无法仅靠现有点表闭环。具体缺口见第 4 节。

## 2. 通信角色与地址规则

| 项目 | V6.0 要求 | VirtualPlc 实现 | 结论 |
|---|---|---|---|
| 协议 | 推荐 Modbus TCP | Modbus TCP | 一致 |
| PLC 角色 | PLC 接收上位机指令并反馈 | Slave/Server，被动监听和响应 | 一致 |
| 上位机角色 | 主动轮询、写命令 | Master/Client | 一致 |
| PLC 扫描周期 | ≤10ms | 默认 10ms | 一致 |
| 上位机轮询周期 | ≤50ms | 接入说明要求约 50ms；由上位机实现 | 接口约束一致 |
| 心跳超时 | 连续 3 秒 | 默认 3000ms | 一致 |
| 地址口径 | 文档 0x/4x 地址 | 文档地址一基，Modbus PDU 偏移零基 | 一致 |
| 功能码 | 线圈和 Holding Register 读写 | 01、03、05、06、15、16 | 满足点表读写 |

默认连接参数为 `127.0.0.1:1502`、Unit Id `1`。Modbus TCP 中的 Server 对应传统术语 Slave，二者指同一个从站角色。

## 3. 已落实的闭环和互锁

| 规范行为 | 实现结果 |
|---|---|
| PLC 心跳翻转，PC 回写相同值 | 已实现；仅匹配当前 PLC 心跳值的响应会刷新有效心跳时间 |
| 心跳 3 秒超时后停止动作并禁止新动作 | 已实现；置位 `PLC_System_Fault`，当前动作失败，后续动作被互锁 |
| `PC_System_Ready=1` 才允许动作 | 已实现 |
| `PLC_Mode_Auto=1` 且无故障才允许动作 | 已实现 |
| `Soft_Stop_Cmd=1` 切断正在执行的动作 | 已实现；当前动作立即转入对应失败状态，并禁止新动作 |
| 人工介入时禁止运动 | 已实现；`Manual_Zone_Occupied=1` 会终止当前动作并禁止新动作 |
| 区域配置完成后 PLC 确认 | 已实现 `Zone_Config_Ready` 0→1 与 `Zone_Config_Ack` 反馈 |
| 区域未确认前不得开始运动/翻转/分拣 | 已实现；上述三类动作要求 `Zone_Config_Ack=1` |
| XY/Z 双状态反馈 | 已实现运动中、到位和超时/失败状态 |
| 翻转完成后反馈并校验角度 | 已实现 90°/180°结果及角度不符故障注入 |
| 分拣必须携带唯一槽位号 | 已实现；执行分拣时 `Sorting_Part_Index=0` 会拒绝并返回失败 |
| 分拣成功、抓取失败、满盘 | 已实现状态 2、3、4及故障注入 |
| 托盘锁紧/解锁与失败 | 已实现状态 0、1、2 |
| PLC 只写 PLC→PC 点，上位机只写 PC→PLC 点 | 已实现方向校验；越权写返回 Modbus 异常 |
| PLC 不保存业务任务、检测面和算法结果 | 已实现；这些内容未进入 PLC 点表 |

动作命令采用 `0 → 非 0` 触发。再次执行同一命令前，上位机必须先清零。V6.0 未定义命令清零责任和重复命令序号，因此这是当前双方需要冻结的握手约定。

## 4. V6.0 点表尚不能闭环的事项

### 4.1 故障码没有地址

规范要求 PLC 向上位机发送 01～05 故障码，但点表只提供一位 `PLC_System_Fault`，没有故障码寄存器。当前实现只能通过该线圈给出“有故障”，详细模拟故障可从管理 API 查看。正式联调前需要在 ICD 中增加只读故障码寄存器并定义复位方式。

### 4.2 动态区域满盘判断缺少输入

规范要求 PLC 根据 `NG_Zone_Count` / `Pending_Zone_Count` 判断目标区域是否已满，但点表没有“本次分拣目标为 NG 还是 Pending”、各区域当前占用量或目标放料槽位。PLC 无法只凭现有信号计算区域是否已满。当前实现支持 `Sorting_Cmd=2` 或故障注入产生满盘状态 4；正式闭环需要补充目标区域和占用/目标槽位信号，或明确满盘完全由机械传感器给出。

### 4.3 分拣位置冲突缺少物理反馈

验收项要求识别“命令槽位 5、实际抓取槽位 6”，但点表只有上位机下发的 `Sorting_Part_Index`，没有 PLC 读取到的实际槽位反馈。因此虚拟 PLC 能检查索引非零，却不能比较命令槽位和实际槽位。应增加实际槽位只读寄存器或明确传感器校验方式。

### 4.4 坐标编码未定义

X/Y/Z 和当前位置均为单个 16 位寄存器，但规范未定义单位、比例、符号、范围和溢出规则。当前实现按原始 `ushort` 传递，不能据此确认真实设备的毫米值。PLC 与上位机团队需要共同冻结编码，例如“有符号 0.01mm”。

### 4.5 重试和重复命令细节未定义

`Retry_Cmd` 给出了 1/2/3 的业务含义，但没有定义重试时原命令参数的保留范围、命令清零方、确认信号和断线后的幂等规则。当前模拟器提供状态复位基础能力；生产版 ICD 需要补充完整状态机。

### 4.6 断电后的编码器位置

规范描述真实 PLC 断电后由编码器保持物理位置。虚拟 PLC 的进程内复位会保留当前位置，但进程完全退出后没有实体编码器，位置不会跨进程保存。这是虚拟设备与真实硬件的边界，断电恢复验收仍需在真实 PLC 上完成。

## 5. 最终判定

VirtualPlc 的 Modbus 点表与 V6.0 资料完全对应，主从角色正确，且点表能够表达的关键动作闭环已实现并加固。由于第 4 节列出的资料缺口，当前不能对“整份 PLC 交互规范严格完整落地”给出肯定结论。若要作为最终成交接口，建议先补发一版 PLC ICD，至少增加故障码、分拣目标区域、实际槽位反馈，并冻结坐标和重试握手定义。
