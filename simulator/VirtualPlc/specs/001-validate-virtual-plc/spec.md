# Feature Specification: VirtualPlc 全量测试验证

**Feature Branch**: `001-validate-virtual-plc`

**Created**: 2026-09-17

**Status**: Ready

**Input**: User description: "用 speckit 帮我整个 virtualPlc 做测试验证，所有改动或者生成项都得在 pj1 目录下"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 验证公开接口和点表 (Priority: P1)

作为联调负责人，我需要确认虚拟 PLC 对外暴露的 Modbus TCP、HTTP 状态接口和监控页面
与约定点表一致，从而允许上位机按既定地址和方向接入。

**Why this priority**: 地址、方向或协议响应错误会使所有后续设备流程失去可信基础。

**Independent Test**: 启动服务，读取完整点表和状态，再对所有支持的 Modbus 功能码、
越权写入和非法请求执行黑盒验证。

**Acceptance Scenarios**:

1. **Given** 服务已启动，**When** 读取健康、监控和地址表接口，**Then** 页面可用且
   8 个线圈、21 个保持寄存器的地址、偏移、名称和方向与 CSV 点表一致。
2. **Given** Modbus 客户端连接到 Unit Id 1，**When** 使用功能码 01、03、05、06、15、16，
   **Then** 合法请求成功，事务号和写入回显符合协议。
3. **Given** 客户端发送不支持功能码、非法地址、非法值、错误 Unit Id 或越权写入，
   **When** 服务处理请求，**Then** 分别返回约定的 Modbus 异常且服务保持可用。

---

### User Story 2 - 验证完整动作流程和互锁 (Priority: P1)

作为上位机开发人员，我需要确认区域配置、托盘锁、XY/Z、翻转、分拣、重试和心跳
按约定握手，且系统就绪、区域确认、软停和动作互斥会阻止不安全动作。

**Why this priority**: 这是虚拟 PLC 能否代替真实下位机完成联调的核心价值。

**Independent Test**: 通过公开接口从复位状态执行一次完整正常流程，再逐项触发互锁、
非法命令、重复命令和并行动作。

**Acceptance Scenarios**:

1. **Given** 心跳正常且系统就绪，**When** 完成区域配置后依次锁盘、移动、翻转和分拣，
   **Then** 每个动作经历运行中和终态，位置、角度及分拣结果正确。
2. **Given** 系统未就绪或区域未确认，**When** 发出动作命令，**Then** 动作被拒绝并返回
   对应失败状态。
3. **Given** 动作正在运行，**When** 收到软停或另一动作命令，**Then** 当前动作按规则停止
   或继续，冲突动作失败，且状态没有相互污染。
4. **Given** 同一个动作已执行，**When** 未先清零就重复相同命令，**Then** 不触发新动作；
   **When** 完成 0→非0 重触发，**Then** 新动作被执行。

---

### User Story 3 - 验证故障、兜底和恢复 (Priority: P1)

作为验收人员，我需要覆盖所有故障注入、流程兜底分类和复位恢复，以确认安全类故障
会阻断、超时类错误会记录后继续、非设备失败按模拟策略继续。

**Why this priority**: 故障语义直接决定联调结果是否安全且可解释。

**Independent Test**: 对每个公开故障逐一复位、注入、触发对应动作、检查状态和恢复，
并遍历全部流程失败分类。

**Acceptance Scenarios**:

1. **Given** 某个一次性动作故障已注入，**When** 执行对应动作两次，**Then** 第一次产生
   预期失败，第二次恢复正常。
2. **Given** 急停、人工介入或心跳超时，**When** 发出动作，**Then** 系统故障或安全互锁
   生效，复位或人工确认后状态按约定恢复。
3. **Given** 任一流程失败分类，**When** 调用流程决策接口，**Then** continueFlow、
   shouldReportError、isFallback 和 decision 符合分类策略。

---

### User Story 4 - 获得可复跑的验证证据 (Priority: P2)

作为项目负责人，我需要一次命令即可执行验证，并得到需求覆盖、检查明细、环境限制和
最终判定，以便交接和复验。

**Why this priority**: 可复现报告让测试结论可审计，而不是依赖一次终端输出。

**Independent Test**: 在 `pj1` 内运行验证脚本，检查退出码、控制台汇总和 JSON/Markdown
报告是否一致且不在目录外生成文件。

**Acceptance Scenarios**:

1. **Given** 本机只有 .NET 8 SDK，**When** 执行验证，**Then** 同源兼容主机完成行为测试，
   报告明确将生产 .NET 10 构建标记为 NOT RUN。
2. **Given** 任一检查失败，**When** 验证结束，**Then** 进程返回非零退出码并在报告中给出
   失败检查名称和原因。
3. **Given** 所有自动检查通过，**When** 验证结束，**Then** 报告记录总数、通过数、耗时、
   环境信息和已知规范限制。

### Edge Cases

- Modbus 请求的数量为 0、超出协议上限、PDU 长度错误或访问存储边界之外。
- 多点写入跨越未定义地址或混合 PLC/PC 所有权时，整次写入必须拒绝且不能部分生效。
- 坐标使用 0、65535 等边界值时，原始无符号值和状态接口的有符号解释保持一致。
- 动作执行期间收到另一个动作命令、软停、安全故障或复位。
- 故障注入名称或流程失败分类无效时，HTTP 返回客户端错误而服务继续可用。
- 暂停心跳时客户端仍连接，以及客户端停止应答导致超过 3 秒超时。
- 随机兜底结果无法固定时，仅验证结果集合和控制字段，不依赖单次随机值。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 验证系统 MUST 核对公开地址表与 `docs/plc-address-map.csv` 的全部 29 个点位。
- **FR-002**: 验证系统 MUST 覆盖 Modbus 功能码 01、03、05、06、15、16 的成功路径。
- **FR-003**: 验证系统 MUST 覆盖非法功能、地址、数据、Unit Id 和读写方向的异常路径。
- **FR-004**: 验证系统 MUST 验证健康接口、监控页面、静态资源、状态接口和地址表接口。
- **FR-005**: 验证系统 MUST 覆盖心跳、系统就绪、区域配置和托盘锁握手。
- **FR-006**: 验证系统 MUST 覆盖移动、翻转、分拣、命令清零重触发和重试复位。
- **FR-007**: 验证系统 MUST 覆盖系统未就绪、区域未确认、软停和动作互斥。
- **FR-008**: 验证系统 MUST 覆盖全部 9 种故障注入及其终态或恢复行为。
- **FR-009**: 验证系统 MUST 覆盖全部 11 种流程分类在成功和失败时的决策规则。
- **FR-010**: 验证系统 MUST 校验复位会清除故障、PC 可写量和动作状态。
- **FR-011**: 验证系统 MUST 以单条入口命令运行，并以退出码表达自动检查结果。
- **FR-012**: 验证系统 MUST 在 `pj1` 内生成机器可读和人类可读的验证证据。
- **FR-013**: 验证报告 MUST 区分自动测试失败、未执行环境门禁和已知规范缺口。
- **FR-014**: 验证不得改变生产项目的 .NET 10 目标框架或依赖集合。

### Key Entities

- **Validation Check**: 一个带需求编号、名称、状态、耗时和诊断信息的原子检查。
- **Validation Run**: 一次完整执行，包含环境、开始结束时间、检查集合和最终判定。
- **PLC Point**: 点表中的区域、文档地址、PDU 偏移、名称、方向和值语义。
- **Fault Scenario**: 故障名称、触发动作、预期终态、清除方式和是否一次性消费。
- **Environment Gate**: 生产构建所需条件及 PASS、FAIL 或 NOT RUN 状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 29/29 个公开点位均通过 CSV、HTTP 元数据和运行时值的交叉核对。
- **SC-002**: 6/6 个支持的 Modbus 功能码至少各有一个成功检查，4 类协议异常均有检查。
- **SC-003**: 正常动作、互锁、9/9 个故障和 11/11 个流程分类都有可重复的自动验证证据。
- **SC-004**: 完整自动验证在 60 秒内结束，且连续两次执行不会因残留状态失败。
- **SC-005**: 自动检查全通过时返回码为 0；任一检查失败时返回非零码。
- **SC-006**: 所有新增或生成文件都位于 `/home/ubuntu/disk/pj1` 下。
- **SC-007**: 报告明确标出当前环境能否完成 .NET 10 生产构建，不以兼容性运行替代该结论。

## Assumptions

- 验证对象是 `VirtualPlc/` 当前工作区内容，默认使用回环地址，测试可选择空闲端口。
- 当前环境只有 .NET 8 SDK；允许用测试专用兼容主机编译相同源文件并执行黑盒行为验证。
- 不接入真实 PLC、相机、MES 或其他硬件/外部服务。
- 源规范已知缺少故障码寄存器、分拣目标区域、实际槽位反馈和坐标编码定义；这些记为
  规范限制，不伪造额外点位来让测试通过。
