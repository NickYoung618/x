# 按工位增量交付顺序（2026-09-17）

V1.3 的检测链至少涉及初始/翻面后 3D、F 托盘码、A/B/C/D 检测相机、E 零件码，以及翻面、旋转、分拣等动作。下表是 PR 边界，不把这些都误称为物理上独立的固定工位；具体机构位置由设备方确认。每阶段先通过自身正反例和跨边界联调，再由对应同学拿同一版本复测。

这张表只限定**中台按站交付与验收**。下位机同学依据[11 组最新工艺图](process-diagrams/upper-lower-v13/README.md)和[全工位派任书](assignments/plc-all-stations-parallel-work-order-20260917.md)提前并行实现全部设备侧能力；中台不必等前一站完成才向下位机提出下一站接口。

| 阶段 | 单独 PR 的终点 | 主要依赖/测试证据 |
| --- | --- | --- |
| S01 初始 3D 定位 | 新鲜 Ready/夹紧 → 公共移至 3D → 定位与 PartId/Epoch=1 → 等待 F | [首工位规格](../specs/005-initial-3d-station/spec.md)、合成 Host 链及故障矩阵；真机另测 |
| S02 F 托盘码与配方 | 公共移至 F → 读盘码 → 场景唯一配方/计划冻结 | 有效码、无码/错码、无/多匹配；生产配方到位前用标记测试样例 |
| S03 A 检测位 | 逐槽移位/到位/A 采图及技术终态 | 可重复图像/算法替身；算法服务另联调；单运动通道 |
| S04 B 检测位 | 逐槽 B 采图，与 A 输入按计划关联 | A/B 相机组输入齐备/缺帧/乱序；不假定质量通过 |
| S05 C 检测位 | 配方需要时逐槽 C 采图 | 独立位置/相机、到位/帧关联及故障 |
| S06 D 检测位 | 配方需要时逐槽 D 采图 | C/D 配对与可选相机组；不虚构拍照次数/阈值 |
| S07 翻面与 3D 重定位 | 整盘逐件翻面、重新扫描、保留 PartId、换 CoordinateEpoch | 这是跨工位动作 PR；运动未知停机、旧坐标/迟到反馈阻断 |
| S08 E 零件码位 | 码绑定既有 PartId | 缺码、错码、重复码及身份关联 |
| S09 特殊旋转/搬运位 | 按已确认的特殊件模板执行 | 机构、配方和动作语义待确认；单独 PR |
| S10 判定、保存与分拣 | 必检项收敛、OK/NG/Pending、关键保存、分拣确认 | 跨工位收尾 PR；故障独立验证，数据落盘后才放行 |
| S11 完整整盘/桌面组合 | 有来源的测试配方、独立虚拟设备、算法/前端、Windows 包 | 单阶段通过不能替代整盘及真实样件验收 |

次序用于降低联调范围，不意味着每阶段只写一个源码模块。每个 PR 要说明本阶段的可运行入口、版本化输入/预期、错误与日志、Linux/Windows 自动测试、设备与界面同学的复测资料，并区分旧 V6、V1.3 与完整整盘证据。当前 main 已有内存业务框架、V1.3 模块/能力状态与默认拒绝、只读 Vue 页、旧协议独立 Modbus 联调和 .NET 10 CI；各工位的 Host 执行链尚未实现。
