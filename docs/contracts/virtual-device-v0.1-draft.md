# 虚拟下位机接口 v0.1 评审草案

**状态：待用户与虚拟下位机负责人共同确认。** 本文不是已冻结的 PLC 点表，也不是已实现的接口。
依据：总体架构 V1.3 第 5、7、10、11、13、18 节及用户指定的普通件首版范围。

## 1. 两个边界

1. **正常设备通信面**：上位机的实际 Modbus TCP 客户端连接独立模拟器。
   Workflow 只认识整体动作和完成事件，不读取寄存器。模拟器只维护设备轴、夹具、夹爪、
   安全、忙闲和当前动作，不决定整盘业务的下一步。
2. **测试控制面**：建议独立本地 HTTP 接口，加载场景、设置时间/随机种子、注入故障、读取动作轨迹。
   该控制面仅用于测试，不能成为正常 Workflow 直接完成业务的捷径。

Motion 的内部 C# 端口与线上的 Modbus 点表是两件事。单元假实现只能证明业务规则；
两进程通过真实 Modbus 读写才能证明协议编码、握手和连接行为。

## 2. 整体动作语义

| 建议动作 | 必需语义 | 结果判据 |
| --- | --- | --- |
| PositionForCapture | 目标 XY、所需成像 Z/扫码 Z、坐标系/坐标批次、相关资源 | 匹配本次动作的到位状态及结果码 |
| FlipPart | 完整抓取点、放置点、目标面/角度、所需机构参数；PLC 封装内部动作 | 该件整体翻面动作完成；整盘轮次由 PC 组织 |
| SortPart | 完整抓取点/放置点、分拣目的地及已冻结决策关联 | 匹配动作完成且物理状态可确认 |
| RequestStop | 指定停止请求及原因；普通业务暂停与设备停止区分 | 明确反馈停止/仍在动作/未知；超时不能等同已停 |
| ReadSnapshot | 当前会话、实际位置、夹爪/夹具、互锁、动作和故障状态 | 可用于状态协调的自洽快照 |

“整盘翻面”是全盘零件完成一轮翻面，不推断机构能一次倒转整个托盘。
扫描及相机触发由上位机采集协调器组织，必要运动仍走整体动作接口。

## 3. 命令和反馈建议字段

| 字段/阶段 | 约束 |
| --- | --- |
| ContractVersion / Capabilities | 握手确认协议版本和是否支持会话、序号、整体动作、停止与故障注入 |
| SessionId + CommandSequence | 共同区分一次命令；重连不能把前一会话完成状态匹配给新动作 |
| ActionKind + Parameters | 完整参数区先写入，提交后 PLC 锁存；执行过程中不读被下一命令覆盖的参数 |
| SubmitSequence | 提交边界；参数完整性、允许提交状态须共同定义 |
| AcceptedSequence | 接收/锁存，不等同物理动作完成 |
| CompletedSequence + ResultCode | 只有匹配会话及序号的完成反馈才推进当前动作；结果码区分成功、失败、拒绝 |
| Busy / ActualState / Fault / Heartbeat | 可确认实际位置、夹爪/夹具、互锁及控制健康；不凭一个陈旧 done 位完成新动作 |

线上待确认：寄存器地址、数量、整数宽度、浮点格式和字序、单位、符号、范围、更新一致性、
会话重启/序号回绕规则、提交确认保持/清除方式、各超时预算和停止优先级。
本草案不填写虚构生产地址、坐标或安全超时值。模拟点表与真实点表可不同，但须显式版本化。

## 4. 超时、重复、重连

- 同一已受理命令重复提交不得再次执行物理动作，返回关联状态；保留去重窗口/重启边界须明确。
- 不匹配的旧完成、乱序反馈不能推进新动作。过期坐标禁止用于新运动，旧合法图像计算可继续。
- 完成反馈丢失后先查询；无法确认实际结果进入 Unknown，禁止盲目重发抓取、翻面和分拣。
- 模拟器重启后必须公开丢失/保留了哪些状态；上位机重连不自动恢复运动。
- 若最终 PLC 不支持严格序号，提供明确兼容握手与单动作模式；不声称完全等价或严格 exactly-once。

## 5. 测试控制面提案

下面路径和 JSON 字段均为提案；确认后才编写线上契约测试，不当作同学已接受。

| 建议请求 | 输入/输出 |
| --- | --- |
| POST /test/scenarios/load | scenarioId、seed、initialDeviceState；返回 scenarioRevision |
| POST /test/faults | faultId、目标命令/动作、触发点（受理前/执行后/反馈前）、故障参数 |
| GET /test/snapshot | 轴、夹爪、占用、会话、当前动作、故障 |
| GET /test/trace | 单调事件序号、命令关联、受理/执行/完成轨迹；用于独立核对执行次数 |
| POST /test/handoffs/confirm | 混合模式人工交接记录，不能把人工真实搬运标成模拟动作 |

支持故障至少：延迟、丢反馈、旧完成、重复/乱序、断连/重启、抓空、目标槽满、互锁触发。
相机丢帧和算法超时由各自模拟适配器注入，不能都塞入虚拟 PLC。

## 6. 冻结前评审清单

共同确认整体动作列表及完整参数、正常点表和反馈保持规则、会话/序号生命周期、停止/重连、
测试控制面、每个故障的预期行为、版本兼容。由两边分别实现，再用同一测试场景对照。
本草案完成仅表示有可评审接口；独立模拟器联调和真实 PLC 验收仍未执行。
