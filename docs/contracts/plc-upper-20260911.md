## 地址、数据与访问口径

新 DOCX 使用 `0x` 表示 Coil 区、`4x` 表示 Holding Register 区。由于出现 `4x000B/000D/000F`，**隔离虚拟测试**把后缀解释为十六进制的一基点号，PDU 偏移为数值减 1；如 `4x000B → FC03/FC16 偏移 0x000A`、`4x0020 → 偏移 0x001F`、Coil `0x0010 → 偏移 0x000F`。旧 V6 模拟器的数字后缀为十进制一基，**绝不可对同一设备同时使用这两种表**。厂商真实设备的基数/零一基、Unit ID 和允许的功能码尚待现场报文签认。

Bool 使用 Coil；Int16 一寄存器；坐标和高度为 IEEE 754 Float32，连续两寄存器。单寄存器 Modbus 报文字节是大端；设备 Float32 的两字及内部字节排列需以已知值校准。代码支持 ABCD、CDAB、BADC、DCBA 并要求显式配置，无生产默认字序。坐标系、单位、符号、范围与公用目标位仍未签认；`synthetic-machine`/`synthetic-mm` 仅测试标签。

| 区/点号 | PDU 偏移 | 方向与定义 | 本轮接口语义 |
| --- | ---: | --- | --- |
| Coil `0x0001/0002/0003` | 0/1/2 | PLC 心跳、PC 回显、PC 初始化完成 | Ready 不等于写入确认，须读 `0x0008` |
| Coil `0x0004/0005/0006` | 3/4/5 | PLC 故障、自动模式、PC 软停请求 | 软停写成功只算请求受理 |
| Coil `0x0007/0008/0009` | 6/7/8 | PC 复位、PLC Ready、PC 重启 | 复位职责冲突，暂不自动写 7/9 |
| Coil `0x0010/0011` | 15/16 | PLC 人工区占用、PC 人工翻面确认 | 占用时禁运动；确认后仍须人工对账 |
| Register `4x0001/0002` | 0/1 | PC 移动命令 1–5、PLC XY 运行/到位/超时 | 泛化用途，不等于专属 3D/F/A–E 动作 |

| Register `4x0013` | 18 | PLC Z 状态 0 闲、1 动、2 到、3 错 | 不可用 XY 到位代替 Z 到位 |
| Register `4x0015/0016/0017` | 20/21/22 | PC 目标面、PLC 翻面状态、PLC 实际面 | 值为面号 1…N，**不是角度 90/180** |
| Register `4x0020/0021/0022` | 31/32/33 | 槽位号、分拣触发、结果 0–4 | 缺整体取/放目标，不开放完整分拣 |
| Register `4x0023/0024` | 34/35 | PC 锁盘、PLC 锁盘状态 0/1/2 | 物理夹紧以状态为准；实体按钮状态未给地址 |
| Register `4x0025/0026/0027/0028` | 36–39 | NG/待定容量、配置就绪、配置 ACK | 与首次 3D/F 的顺序冲突见下 |
| Register `4x0029` | 40 | PC 重试/跳过/队列复位 | 无命令关联时不自动使用 |
| Coil `0x0020/0021`，Register `4x0030`–`4x0036` | 31/32，47–53 | 示教模式/确认、点号与三轴 Float32 | 示教业务数据归上位机；现场权限待定 |

## 按原时序图核对的流程差异

| 时序图要求 | 9 月 11 日点表能力/冲突 | 本轮处理及下一步 |
| --- | --- | --- |
| 安全检查 → 实体按钮 → PLC 夹紧 → 中台获知到位 | 有 Fault/Auto/报警/锁盘，**无实体按钮和全部安全单项当前状态** | 只读取已给点位，不能从“锁盘=1”反推按钮或全部互锁；补状态/事件定义 |
| **先移至 3D，采点云由中台定位；再移至 F，读盘码/配方** | 文档 §3.1.1 要先识别盘码、配置区域 ACK，再发“去上料位” | **流程按图**；不为首 3D 编造 NG/待定容量。`ConfigureZones` 独立于 PC Ready/锁盘；MoveTo3D 和 F 的命令映射/公共目标待补 |
| A/B/C/D 共用成像 Z，E 独立扫码 Z；取放 Z 独立 | 提供 Camera/Scan/Grab 三目标 Z 与一个实际 Z，移动用途仅 1–5 | 三类 Z 分开编码；各轴独立实际到位/是哪一个 Z 尚待定义 |
| 翻面是含取/放目标的整体动作，完成后继续下一面 | 仅目标面号/状态/当前面，无夹爪/整体动作参数 | 新端口按**面号**；完整翻面动作仍未可签认。V1.3 §5.3 强制重扫，保留 PartId、更换 CoordinateEpoch |
| 特殊件取料到旋转位、旋转角度、检测、回放 | **无旋转命令/角度/状态/取放坐标点位** | 不从 V6 的 90/180 翻面命令推造旋转；类型 2–4 参数另待配方/机构资料 |
| PC 给取料/放料目标与去向，PLC 完整分拣取放后反馈 | 有槽位号与分拣状态，无完整双端点/去向/夹爪与唯一完成关联 | `SubmitSort` 明确 `Unsupported`；不能只写槽位号就称整体分拣完成 |
| 超时、停止、断线后对账 | 有心跳/软停/报警，但无 Session/CommandSequence/AcceptedSequence/停止完成状态 | 虚拟隔离测试只做本轮运行→完成；真实设备写入关闭，断线/未知不重发，需版本化扩展或双方签认受限握手 |

协议 §4.3 写 PC 下发 `System_Reset_Cmd` 做机构回零；§5.2 又写初始化按钮归 PLC 触摸屏、上位机只读就绪，两段需要设备方消歧。协议说“上位机崩溃时下发软停”在进程已崩溃时不可实现，应由 PLC 的 3 秒失联看门狗独立动作；PC 在仍运行时可发软停请求，不能据此宣称实际已停。

## 本分支可验证范围与待签认

- **已实现**：新合同严格选择、显式字节排列、只读快照、回环虚拟设备的基本锁盘/区域配置、单次移动与面号翻面有限握手、异常锁定；Host 工程新协议入口只读；旧 V6 探针保留。真实配置即使字段齐全也拒绝动作。
- **须由下位机负责人提交/双方签认**：地址及 Unit ID 实测、已知 Float32 往返和坐标系/单位/限位；首 3D 与 F 命令/示教目标、首次区域配置顺序；实体按钮/互锁及分轴状态；命令唯一关联、停止完成/超时/断线/重启对账；翻面整体取放、特殊旋转、分拣双端点与去向/夹爪状态、复位责任；新版独立虚拟 PLC 的版本化点表与轨迹。完成后才放开相应真实动作。
- **测试证据分层**：旧 V6 服务与旧探针；本分支新点表独立 TCP 测试服务；正式新版独立虚拟 PLC 与中台 Host；Windows 真机；完整整盘。各层不可互代，见 [009 验证记录](../../specs/009-plc-protocol-alignment/validation.md)。
