## 2. 线缆口径与现有点位

### 2.1 地址和数据规则

- [P] Modbus TCP：PLC 为 Server/Slave，PC 为 Client/Master。单寄存器为 16 位；坐标和高度为 IEEE 754 Float32，连续 **两**寄存器；面号为 Int16，不使用 V6 的 90/180 度翻面命令。
- [S] PR #9 的隔离测试合同为 `plc-upper-20260911-hex1-f32`：点号后缀按**十六进制一基**解析，PDU 偏移 = 点号数值 − 1。例如 `4x000B → 0x000A`，`0x0010 → 0x000F`。厂商实机的进制、零/一基、Unit ID 和允许功能码仍为 TBD；旧 V6 的十进制一基点表不能混用。
- [P] 读取线圈用 FC01，读取保持寄存器用 FC03；单线圈写 FC05，单寄存器写 FC06，连续寄存器写 FC16。以下功能码是按数据类型提出的 Modbus 访问方式；具体写权限仍须 PLC 方签认。`4x0027` 虽在原表标为 Bool，地址属于保持寄存器，候选写法为 FC06，不当作 Coil。
- [P] Float32 两字及字内字节排列未签认。PR #9 编解码支持 `ABCD/CDAB/BADC/DCBA` 且要求显式配置；真实设备**没有默认排列**。坐标系、单位、符号、范围、限位和到位公差均为 TBD。
- [S] 报文校准例：测试 Unit ID `1`、ABCD、`123.5f = 42 F7 00 00`，向 `4x0003` 写两字的请求为 `00 01 00 00 00 0B 01 10 00 02 00 02 04 42 F7 00 00`。这只核对 PDU 偏移、FC16 和字序，不是实际坐标或实机报文口径。

## 3. 所有动作共用的语义草案

### 3.1 命令身份、参数锁存和反馈

1. [E] PC 在发动作前持久记录 `TrayRunId`、`OperationId`、单调 `CommandSequence`、动作类型、目标参数、合同版本和发送意图；同一物理动作不得生成第二个 ID 自动重发。PLC 接收时原子锁存完整参数，回显设备会话、序号、动作类型及参数摘要。**原协议无这些线缆字段；生产寄存器/线圈、原子锁存方式、PLC 掉电后的保持能力均 TBD。**
2. [E] `Accepted` 只在 PLC 明确回显**本次**锁存序号和接受状态时成立；FC05/06/16 的 Modbus 写确认只说明写入被服务器响应，不能算 `Accepted` 或物理完成。当前 PR #9 的运行状态握手仅适用于隔离单动作测试；不能证明断线、迟到和重启后的唯一关联。
3. [E] `Completed` 只在相同设备会话/序号出现终态、物理反馈与锁存目标相符、必要互锁仍满足时成立。XY、各 Z 轴、面号、夹爪/料盘/目标占用均按动作分别核对。坐标公差、刷新周期、稳定采样次数由设备方签认；未定时不得宣称真实到位。
4. [E] 明确拒绝或设备失败为 `Failed` 并保存原始状态/报警码；通信中断、期限超出、反馈矛盾或缺唯一关联为 `Unknown/RecoveryRequired`。`Unknown` 不自动复位、重试、跳过或重发。`0x0006` 软停写成功只算停止请求送达，实际停止须读取轴/机构静止和安全状态。
5. [D/E] 一个 `OperationId` 的期望物理执行次数为 **0 或 1**；明确拒绝为 0，已受理正常完成为 1，结果未知时次数也记未知，直到设备轨迹与现场对账。重复序号应返回既有状态或明确 `COMMAND_REPLAY`，不得再次动作。独立模拟器必须保存设备侧接收次数、锁存参数、受理/终态时间、实际执行次数和物理终态，不能只用 Host 日志作证据。

### 3.2 超时、停止、重连和重启

- [P] PLC 扫描周期 ≤10 ms、PC 轮询周期 ≤50 ms、心跳失联 3 s；原协议验收示例要求移动不完成时 2 s 内告警。**2 s 先作隔离测试用观察期限 [S]**；各真实动作的设备截止、停止期限及公差按机构逐项 TBD。所有期限从**受理或物理启动的可观测时刻**计算，记录单调时间和 UTC；轮询到期不是物理停止证明。
- [E] 重连先禁止新动作，读取完整安全/报警、位置、面号、夹爪、占用及设备会话/当前或末次命令，再与 PC 持久意图和设备独立轨迹比对。相同序号且物理终态可证明时仅结算旧动作，**不重发**；无法证明则 `RecoveryRequired`，人工核实现场。PLC 原协议称掉电后不保留业务进度，若设备也不保留命令关联，则跨重启无法自动证明“已执行/未执行”。
- [E] `StopAndReconcile` 首先关闭新动作准入，再发受控软停请求；急停、门禁、光栅等由硬接线/PLC 独立保护。停机后读取各轴/机构实际静止与占用，并对账在途命令。原协议 §4.3 的 PC 复位线圈与 §5.2 的 PLC HMI 初始化按钮归属冲突；签认前不自动写 `0x0007/0009`，也不将复位当继续任务。

### 3.3 草案语义错误码

以下是上位机与模拟器**语义码 [E]**，不是原协议的 PLC 数值编码；原始报警位和状态值必须同时保留：`NOT_READY`、`BUTTON_NOT_PRESSED`、`INTERLOCK_OPEN`、`NOT_CLAMPED`、`CLAMP_FAILED`、`COMMAND_REPLAY`、`PARAMETER_NOT_LATCHED`、`TARGET_OUT_OF_RANGE`、`XY_NOT_REACHED`、`Z_NOT_REACHED`、`FACE_MISMATCH`、`ROTATION_MISMATCH`、`PICK_EMPTY`、`GRIPPER_UNKNOWN`、`TARGET_FULL`、`PLACE_FAILED`、`STOP_UNCONFIRMED`、`TIMEOUT_UNKNOWN`、`DISCONNECTED_UNKNOWN`、`STALE_OR_WRONG_FEEDBACK`、`RECONCILIATION_REQUIRED`、`UNSUPPORTED_WIRE`。设备方需给出可机读的数值码/位映射后才冻结。

## 4. 首盘顺序冲突与 S01 最小链

[D] 总时序图步骤 **1–21** 是安全/实体按钮/夹紧 → `MoveTo3D` → 上位机触发 3D 并定位 → `MoveToF` → 上位机触发 F 读盘码。9 月 11 日协议 §3.1.1 则要求先识别盘码、下发 `NG_Zone_Count/Pending_Zone_Count` 并收到 ACK，再发首次移动；此时盘码尚不存在，无法填写真实容量。`XY_Move_Cmd=1…5` 也没有专属 3D/F 公共位或可签认的目标坐标。

**供双方核对的可执行扩展草案 [E]：**

1. 将动作准入分为 `PreIdentification` 与 `Configured`。在 `PreIdentification` 仅允许安全检查、实体按钮、夹紧、`MoveTo3D` 和 `MoveToF`；不允许零件检测、翻面、分拣、解锁。PLC 对这两次公共位移动仍实施全部物理互锁、限位和独立完成反馈；设备方须签认两公共位的目标来源、编码和到位条件。
2. `PC_System_Ready` 只表示 PC 初始化完成，不冒充区域配置 ACK。首次 3D/F 前**不写假 `NG/Pending` 容量，不置位 `Zone_Config_Ready`**。若现有 PLC 程序规定未收到 Zone ACK 时任何移动都不能执行，须由 PLC 方提供明确的准备阶段许可/命令扩展；在此之前仅做标为 [S] 的隔离虚拟测试，不向真实 PLC 发动作。
3. F 读得盘码并由中台解析有效配方后，PC 才给出真实区域容量及目标参数，写 `4x0025/0026`、置 `4x0027`、读 `4x0028=1`，进入 `Configured`。区域配置与 `SetPcReady`、锁盘是不同事务；原协议中的“PLC 内部坐标表更新”与 PC 掌握坐标库的责任需再签认。容量为 0 的合法性及禁分拣策略亦 TBD，不以 `1/1` 占位。
4. 本任务指定的隔离联调终点是 **`MoveToF` 实际到位**：Ready/夹紧/互锁 → `MoveTo3D Accepted+Completed` → 独立 3D 采集 → `MoveToF Accepted+Completed`；F 相机触发和读盘码仍由中台采集侧负责。[PR #7](https://github.com/NickYoung618/x/pull/7) 当前 S01 工程入口停在 `WaitingTrayCode` 且不执行 F 请求，因此要让**同一 Host 链**走到 F 位，中台须在其流程/装配中接入这一步；本合同不把 PR #7 既有测试替身当作已完成三进程链。

## 7. 独立 3D 相机模拟接口草案

[D] PLC `MoveTo3D Completed` 后由**中台**触发 3D 相机；设备模拟进程只返回固定合成点云/深度帧或可读取引用，不返回槽位、`PartId`、配方或质量结论。中台负责帧读取、合成定位器和 `IPlacementLocator` 结果。3D 采集本身不是 Modbus PLC 点位。[E] 进程传输形式、端口、帧格式、真实 SDK 和标定均未签认，**本节先列评审字段，不冻结 HTTP 路径**。

| 请求 [E] | 响应 [E] | 模拟器必须保存的独立轨迹 |
| --- | --- | --- |
| 合同版本、`RequestId`、`TrayRunId`、`ProposedEpoch`、期望合成设备 ID、到位证据引用及请求期限 | 原样回显 ID/盘次/Epoch；设备/固件版本、采集时间、`synthetic` 来源、固定帧 ID/可读取引用、长度与 SHA-256、帧格式；失败时稳定设备错误与是否已触发 | 收到/接受/采集/响应时间、输入 ID、固定帧版本、触发次数、返回引用、故障与实际设备会话 |

首个固定样例 [S] 可使用两个可定位的合成目标，但**槽位 `s1/s2` 只由中台定位器产生**。模拟器需能确定性预置正常帧、坏帧、超时、断线、迟到及错 ID；控制接口仅预置设备事实，业务触发必须经过中台采集客户端。中台必须校验帧与请求/盘次/批次/来源一致，错或迟到结果不得推进 `MoveToF`。真正帧二进制格式、传输协议、错误码和超时预算待双方评审后形成 3D 附录。
