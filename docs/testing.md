# CI 测试如何产生、执行与判定

基准：总体架构 V1.3 + 最新界面原型 + 用户已确认的普通件测试样例。
**CI（持续集成）负责自动执行测试；测试期望来自规格和独立设备轨迹，不能由被测代码自己证明自己正确。**

## 1. 从需求到可执行测试

每个功能按以下链条维护：`spec.md 验收场景 → 测试编号与预期 → 测试代码 → CI 作业 → 证据`。
Spec Kit 用来组织这些文件和任务，不会仅凭一张原型自动得出正确的业务规则。
可以生成测试骨架或用 Playwright 录制点击步骤，但断言必须补上业务身份、状态、数据与动作次数检查。

本轮已生成：

- `Inspection.Domain.Tests`：计划中的面/相机/零件顺序、翻面/重扫标记、零件编号、可替换配置与无效输入；尚不验证真实执行屏障。
- `Inspection.Host.Tests`：存活、生产未就绪、测试计划查询、未实现动作不接受。
- `.github/workflows/ci.yml`：Linux/Windows 核心还原、构建、测试、发布、发布进程检查、证据上传。
- `scripts/smoke-host.ps1`：真实启动发布出的 Host，调用接口并清理自己启动的进程。

这是基础工程测试。以下流程/协议/界面案例是后续必需用例，尚未以空测试或 skip 冒充已实现。

## 2. 测试层次与触发

| 层 | 在哪里运行 | 什么时候 | 检查内容 | 当前状态 |
| --- | --- | --- | --- | --- |
| 核心单元/HTTP | GitHub ubuntu-24.04 + windows-2022 | 每次 PR、main push、手动 | 规则、边界、接口、发布启动 | 已编写，实际结果见 validation.md |
| Vue 组件/浏览器 | GitHub 托管 runner | 前端提交后每次 PR | 权限显示、按钮状态、筛选、弹窗、离线资源；浏览器连真实测试 Host | 待前端实现接入 |
| 独立虚拟设备集成 | 托管 runner 可执行的独立模拟器；若限 Windows 则 Windows 作业 | 实现与共用契约对齐后每次 PR/合并 | 实际 Modbus 客户端、两进程握手、超时/断连、动作轨迹 | 已取得 VirtualPlc 副本审查；待 V1.3 差异处理及中台实际客户端接入 |
| Windows 部署冒烟 | 自有 Windows 的 gaode-staging runner | 指定已通过 CI 的构建 | 下载同一构建、独立目录运行、路径/运行库/权限/进程 | 工作流已准备，runner 未注册 |
| WPF/WebView2 完整流程 | 自有 Windows 交互桌面，串行 | 可交付构建、夜间回归 | 从登录到整盘完成，再查数据、媒体、分拣 | 待桌面和完整闭环实现 |
| 真机/真实算法 | 设备现场或相应硬件环境 | 逐步接入、版本验收 | 真实坐标、互锁、图像、精度、GPU、节拍 | 未执行 |

Windows 托管 runner 与用户的 Windows Server 2019 是不同环境；前者通过不等于后者部署通过。

## 3. 普通零件首版的核心验收矩阵

| 编号 | 注入/操作 | 必须观察的结果 | 层 |
| --- | --- | --- | --- |
| FLOW-001 | 2 件×2 面×AB 启动 | 每面 A1/A2/B1/B2；一轮翻面后整盘重扫；相同 PartId；8 次采集 | 规则 + 集成 + Windows E2E |
| PREP-001 | 初始 3D 后 F 扫到已配置托盘码 | 托盘码与检测场景匹配唯一方案，冻结版本后生成计划；不依赖先手选方案才能首次扫码 | 集成 + Windows E2E |
| PREP-002 | F 无法读码、未知码或方案匹配歧义 | 准备失败；不沿用旧/默认方案开始检测；更换场景后按明确规则重新准备 | 集成 + Windows E2E |
| FLOW-002 | A 有图，B 丢帧 | 对应采集/依赖明确失败，资源释放；无可靠 NG 则 Pending；不死等、不伪造 B 图 | 集成 |
| FLOW-003 | 面1算法迟到，已翻面重扫 | 面1合法图像结果仍归面1；旧坐标禁止用于新的移动 | 集成 |
| FLOW-004 | 重拍后旧 Attempt 结果到达 | 旧结果不能覆盖当前有效尝试或重复计数 | 规则 + 集成 |
| FLOW-005 | 普通算法超时/Worker退出 | 每个已受理任务有有效终态；独立分支继续；依赖失败传播 | 集成 |
| FLOW-006 | 定位或关键身份失败 | 停止依赖该定位/身份的动作，不按普通算法失败继续 | 集成 |
| FLOW-007 | 算法慢、缓存/配对/归档积压 | 采集前控制准入；预留后半组采集容量；控制消息仍可处理 | 集成 |
| FLOW-008 | 分拣冻结后迟到结果 | 决策/去向不自动改变；补充结果单独留痕 | 规则 + 集成 |
| DEV-001 | 受理成功、完成反馈延迟 | UI 显示执行中，不能把 Accepted 当 Completed | 协议 + E2E |
| DEV-002 | 动作执行后丢完成反馈 | 按会话/序号查询；未知则暂停协调；模拟器轨迹中实际执行次数为 1 | 协议 |
| DEV-003 | 重复/旧序号/乱序/重启 | 新动作不被旧完成推进；重连不自动运动 | 协议 |
| DEV-004 | 抓空/目标槽满/互锁触发 | 相应动作明确失败/暂停，不错误标记分拣完成 | 协议 + E2E |
| DATA-001 | 在意图保存、物理执行、反馈保存间分别中断 | 恢复按事实对账，不盲重发、不伪造完成、不提前放行 | 集成 |
| DATA-002 | 磁盘满/媒体缺失/写入失败 | 保存失败可定位；必要保存未完成时不放行；不存在的帧有明确缺失记录 | 集成 + Windows |
| DATA-003 | 同一零件详情重复打开/程序重启查询 | TrayRunId/PartId/图像/结果一致；导出能与数据库及媒体逐项对上 | E2E |
| UI-001 | 登录、越权、重复启动点击 | 权限来自后端；重复请求不产生两个托盘任务；按钮状态跟随服务快照 | 组件 + E2E |
| UI-002 | 检测中关界面、断开重连 | 按停止策略处理，重连先取带 Revision 快照；不能重置或重复启动任务 | E2E |
| UI-003 | 修改检测方案再保存 | 新版本可查询；正在运行的任务仍用原冻结版本；无权用户被后端拒绝 | E2E |
| UI-004 | 禁止外网，仅允许本地及设备网络 | 页面、字体、图标、算法依赖可离线加载；不存在 CDN 请求 | 浏览器 + Windows |
| UI-005 | 告警确认/解决、Pending复核、导出 | 确认不等于故障已消除；复核有修订记录；筛选统计/导出对应相同数据范围 | E2E |
| UI-006 | Windows 分辨率、DPI、窗口变化 | 登录/主界面/弹窗/报告可操作，关键状态及按钮不被裁切 | Windows |

每个案例必须保存提交号、模式、样例/种子、设备/Worker 版本、实际事件轨迹和测试结果。
独立模拟器动作轨迹不能直接复用上位机 Workflow 日志作为唯一判据。

## 4. V1.3 数据库部署专项

DB-001 空目录初始化、重复初始化、生产目录误选：不覆盖、不重复基础数据、不重置配置。
DB-002 受支持旧版升级、已目标版、过新版/无迁移路径：正确执行或拒绝。
DB-003 Host/查询未释放、双工具、迁移中 Host 自动重启：共同维护互斥有效。
DB-004 备份失败、磁盘满、无权限、中断：保留旧库/现场/日志，禁止生产启动。
DB-005 工具重启：检查实际完成步骤，再幂等继续或受控恢复。
DB-006 旧备份恢复：明确时间点及新增数据影响，验证软件/配方/模型兼容。
DB-007 搬盘/搬机、媒体缺失、路径变化、仅数据库备份：引用/覆盖清楚，源数据保留。
DB-008 Host 无法启动、无设备：独立部署工具仍可核查/恢复，完成后不自动运动。

全部故障实验使用每次运行独立的测试目录或副本；不对生产数据库或其他项目数据注入故障。

## 5. 失败与覆盖记录

失败上传 TRX/JUnit、结构化日志、场景配置、设备动作轨迹、截图/视频/Playwright trace、数据核对结果。
第一次失败及重试结果分别记录；不靠重试转绿隐藏不稳定。
缺少 WPF、模拟器或运行库须明确报“前置条件未满足”，不返回一个假的全流程成功。
仿真通过只证明对应流程规则；不能证明真实检出率、机械安全、节拍或 GPU 稳定性。

入口：`python3 scripts/validate-virtual-plc.py`（SDK按global.json；Python3.12+）。

| 层次 | 用例 | 结果依据 |
| --- | --- | --- |
| 基础规则/HTTP | 原19项 | 当前运行TRX |

| 已有旧协议 | 原13组，含旧POLICY-01 | legacy.json；不是V1.3策略通过 |
| 中台↔独立设备兼容联调 | 两次新Busy→完成、旧反馈重连拒绝、明确失败、动作超时、Unknown后重连拒绝 | Host报文+独立设备日志/状态+summary |
| V1.3完整对接 | Float32新表、会话序号、停止/恢复、完整取放及占用 | 未实现/未运行，等待下位机同学确认接口 |

新CI在两平台运行统一入口，主程序构建与发布实际成功才运行行为检查；检查数、TRX及退出码校验阻止NOT RUN假通过。

## 003 普通整盘中台流程框架

新`Inspection.Application.Tests`测试准备顺序、分面采集、翻面重扫/CoordinateEpoch、旧反馈、普通缺帧、算法乱序与截止、单运动通道及动作超时。执行仍为**接口级状态机与假设备**；不等于真实PLC与扫码/3D/相机/算法连通。
本轮实测与失败尝试见[003验证](../specs/003-ordinary-workflow-foundation/validation.md)。Host默认保持计划预览，未提供生产任务启动入口；方案冻结、技术终态可在内存框架中检查，但质量判定、必要保存、分拣和放行尚未实现。

## 004 下位机候选测试包

`scripts/validate-virtual-plc.py`现在按`Gaode.slnx`枚举当前测试工程，逐份TRX核对程序集身份、非零用例、全通过、无重复或遗漏；旧的固定3份门禁已不适用于003新增的Application测试。下位机同学可用显式`--candidate-dll`和`--contract legacy-v6-u16-snapshot-20260917`运行其独立发布的旧协议模拟器；脚本记录DLL及发布目录哈希，只在回环地址启动该候选，仍由Host真实Modbus客户端执行。候选源码构建记录由提供者附上。

正向结果、负向门禁和未覆盖边界见[004验证](../specs/004-plc-candidate-testkit/validation.md)。候选兼容测试通过只证明该旧协议档案；正式V1.3点表与完整整盘另建用例，保持NOT RUN。
