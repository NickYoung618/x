# 全虚拟覆盖计划：型号、配方、故障

本计划是 V1.3 P1 全虚拟闭环的验收范围。开发过程中可用小样例检查一个新模块；P1 退出时须按已定义的零件和已发布的配方清单逐项执行完整流程，并验证故障与恢复。`2 件×2 面×AB` 仅是开发样例，不能作为全部零件、全部配方或整盘验收的替代。

## 形成可执行覆盖矩阵

每条正式配方记录稳定的 `RecipeId/Version`、型号/场景/料盘码/物料或成组关系、工艺模板、面与相机步骤、搬运与旋转步骤、光源和算法/判定依赖、预期质量分流。发布时生成用例索引，关联源清单单元格、测试数据版本、独立预期轨迹和执行结果。配方修订新建版本；运行中的任务使用冻结版本。

| 故障族 | 注入点与关键断言 |
| --- | --- |
| 准备/身份 | F 码缺失、未知或匹配歧义，初始/翻面 3D 失败，E 码冲突；无可靠身份/坐标不运动，不沿用上一盘配方 |
| 采集/融合/算法 | A/B/C/D 缺帧、坏帧、重复帧；依赖缺输入、Worker 失败/超时、结果迟到/乱序、重拍旧 Attempt；不串件、不伪造图像，形成唯一技术终态和适当 Pending/NG |
| 运动与占用 | Accepted 后延迟/丢完成、重复/旧序号、断连/重启、抓空、满槽、互锁；实际物理动作不盲重发，未知状态暂停对账，旋转夹具占用不被提前释放 |
| 判定/分拣/追溯 | OK/NG/Pending 混盘、截止前后结果、分拣反馈丢失；已冻结去向不自动改写，保存意图先于物理动作，必要保存未完成不放行 |
| 容量/持久化/恢复 | 算法/媒体/数据库变慢或磁盘满；在意图、动作、反馈、文件和数据库提交边界中断；有界背压、恢复事实核对、无虚假完成或丢失证据 |
| 交互/部署 | 重复启动、越权、UI/Host/DeviceHost 重启、数据库初始化/升级/恢复、离线桌面；任务状态与权限不因界面重连重置，部署和查询结果与底层记录一致 |

正常覆盖按**每个已发布配方版本**逐条执行。故障覆盖按**故障机制×适用控制边界**组织：每个故障族至少在一条代表配方验证，涉及不同模板、相机组、夹具占用或质量分流时分别验证；安全关键边界在所有适用模板上验证。再对配方参数边界和若干组合故障做交叉/成对测试。每次新增类型、步骤、配方版本或恢复策略，都必须更新清单和受影响用例。无需制造所有参数取值与故障的无穷笛卡尔积，但不能用一条普通件成功路径代表特殊件或所有错误。

## 执行顺序与通过判据

1. 框架开发阶段：按增量运行规则、状态机、协议和端口的确定性检查；`2×2×AB` 只证明基础编排。当前 004 的旧 V6.0 协议测试和双进程联调属于此层。
2. P1 功能齐备后：冻结覆盖清单与配方集；用同一业务流程、独立虚拟设备及虚拟扫码/3D/相机/Worker 运行所有已发布配方的正常整盘，以及上述适用故障与恢复用例。测试记录种子、时钟、注入脚本、程序/配方/设备版本和跨层证据。
3. 发布候选阶段：Linux/Windows CI 执行可自动化测试；Windows 交互桌面跑登录、准备、整盘、告警、复核、查询/导出及重启恢复；再做重复短测与约定时长的稳定性测试。
4. P2–P4 分别接真实图像/算法、真实协议与硬件，验证精度、机械互锁、节拍及连续生产。全虚拟通过不计作这些阶段通过。

P1 完成需有一份机器可读的已发布配方目录与测试索引：每个应测组合可追到配方/明确不适用决定，每个配方有正常流程 PASS，每个适用故障边界有断言和 PASS，且数据库/媒体/UI/独立设备对账无未解释差异。`NOT RUN`、`SKIP`、缺失配方、缺少独立设备证据或未决定的接口均列为未完成；不能计入通过率。未获批的真实参数可用**显式标记的虚拟配方**测试模板能力，但不得当成该物料的生产配方验收。

下位机同学可先用 004 测试包回归旧协议；正式 V1.3 点表、字序/单位、命令关联、停止与恢复等接口仍待其确认。确认后再为本覆盖计划增加正式协议用例。虚拟设备应对命令给出可控响应和独立轨迹，且不能代替现场安全验证。
