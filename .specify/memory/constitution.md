# Gaode Constitution

## Core Principles

### I. V1.3 为开发与测试的共同基准

必须以用户最新确认及 yyh 目录 2026-09-14 的总体架构 V1.3 为依据。
仓库须保存原文快照、来源和校验值。历史需求及点表只能补充，不能覆盖最新架构。
明确区分设计要求、测试样例与实测结果，未冻结的生产参数不得填成已确认事实。

### II. 单体分层与唯一业务状态所有者

采用一个正式 ASP.NET Core Host，Domain 保持纯规则，Application 编排用例并定义端口，
Infrastructure 实现数据库、媒体和设备适配。界面及 Python 不得直接驱动 PLC 或改业务库。
15 个责任模块不是 15 个进程。流程状态由明确的单一所有者推进，长操作通过完成事件返回。

### III. 机械、身份与结果的边界必须可验证

一套 XY 和共用搬运空间通过统一运动通道协调。普通件按面、相机、槽位顺序批采，
翻面后必须重扫并更新 CoordinateEpoch，保留 PartId 和已有合法图像结果。
必须区分命令受理、物理完成、业务完成；未知动作不得盲目重发。
硬件实时互锁归 PLC/电气。仿真到位不得在真实模式中冒充物理到位。

### IV. 有界流转与明确失败终态

采集前预留容量，回调不得等待算法/存储；图像使用文件引用。
采集、算法和依赖失败必须收敛到明确终态，不无限等待缺失输入。
普通缺陷计算失败可标记后继续，定位、身份及安全前提失效必须停止依赖动作。
OK、NG、Pending 与技术状态、分拣完成分开；冻结后的分拣去向不被迟到结果自动改写。

### V. 关键保存与独立数据库维护

SQLite/EF Core 使用单写入通道及短事务。关键动作须先保存意图，再执行，随后保存匹配反馈。
完成必要结果及媒体保存后才允许业务放行。数据库、文件与 PLC 不承诺全局原子事务。
初始化、升级、搬迁、恢复由独立离线部署工具执行，共享维护互斥并备份核验；
Host 不得在正常启动或生产中静默建库/改表。V1.3 数据库部署测试不得遗漏。

### VI. 同一业务代码与分层测试证据

全模拟、回放、混合联调、真实生产通过适配器切换，同一业务代码承担流程规则。
独立虚拟下位机持有设备状态，不复用 Workflow 决策逻辑。
每项交付注明实际执行的测试、平台、失败及未覆盖范围。
单元测试、真实协议仿真、Windows 桌面与真机验收各自提供证据，不能相互替代。

## Stack and Ownership Constraints

- Vue 3 / TypeScript / Pinia；WPF + WebView2：前端同学负责全部界面及桌面壳。
- .NET 10 / ASP.NET Core；REST 与 SignalR；Python 常驻 Worker；SQLite / EF Core。
- 虚拟下位机及软件对接由另一位同学负责；用户负责其余中台、算法、数据、工程与 CI。
- Linux 用于核心开发，Windows 用于部署；GitHub 托管源码及 CI。
- 首个演示先覆盖普通零件整盘多面全虚拟闭环，随后真实算法和特殊零件。
- 首个可替换测试样例为 2 个零件、2 个面、每面 A/B 各一张；它不是生产检测方案。
- 不引入微服务集群、外部消息中间件或通用脚本引擎。凭据不得进入仓库、规格和测试产物。

## Development Workflow and Quality Gates

遵循 Spec Kit：constitution → specify → clarify（必要时）→ plan → tasks → implement。
规格必须有可检查的验收场景；实现前先明确本阶段依赖和仍未确认的后续边界。
已授权且不依赖未决参数的基础开发继续推进，不用虚假的“95%”数字替代证据。
关键规则和对接变化必须有针对性测试；CI 首先验证 Linux/Windows 核心构建及测试。
模拟契约由本项目起草，再经用户及虚拟下位机负责人确认；草案不得标为双方已冻结。
WPF 运行、真实 SDK、GPU 性能和硬件安全只在对应环境验收。

## Governance

本文件把用户确认的架构要求转成工程规则。用户后续明确指示优先。
修改规则须同时说明依据、受影响规格和验证方式；破坏性修改升主版本，新增规则升次版本，
纯澄清升补丁版本。功能 PR 必须检查适用规则并记录尚未完成的验收，代码完成不等于整机交付。
